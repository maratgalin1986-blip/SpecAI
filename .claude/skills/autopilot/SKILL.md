Порядок взят из открытого фреймворка Autopilot (nick-vels/skills, MIT) и подогнан под этот
репозиторий. Владелец работает удалённо и ничего не согласовывает: все вопросы решаются по
`CLAUDE.md`, `REVIEW.md`, `docs/owner-requests.md`, `tasks/lessons.md`; что решить нельзя —
помечается `PLACEHOLDER — уточнить у владельца` и не блокирует остальное.

Режим по умолчанию — **автомат, глубина средняя**: без пауз между этапами, одна итерация ревью.
Лимит токенов у владельца небольшой, поэтому: один прогон = одна задача дорожной карты, не
больше 8 подзадач, субагенты только на разработку и ревью.

## Этапы

Все артефакты прогона — в `tasks/autopilot/<дата>-<slug>/` (бриф, требования, спецификация,
план, отчёт приёмки); они идут в тот же PR.

1. **Бриф** (`brief.md`). 5–15 строк своими словами владельца: что хотим, для кого, что считать
   успехом. Источник — пункт `docs/roadmap.md` или запрос из `docs/owner-requests.md`. Ничего не
   додумывать сверх написанного владельцем.
2. **Требования** (`requirements.md`). Каждое — отдельной строкой с номером `R1…Rn`, словами
   брифа, проверяемое («R3. Исполнитель видит заявку только после входа»). Отдельно
   «Вне объёма» и «Открытые вопросы» (PLACEHOLDER). Проверить каждое требование на
   противоречие с `REVIEW.md` и решениями владельца — противоречащее вычёркивается с пометкой.
3. **Спецификация** (`spec.md`). Экраны, маршруты API, изменения схемы (только добавление колонок
   с default — правило 2 `CLAUDE.md`), тексты по-русски, права доступа, что происходит при ошибке.
   У каждого пункта — ссылки на номера требований. Новые вопросы владельцу не задаются.
4. **План** (`plan.md`). Задачи `T1…Tk` (≤ 8), у каждой: файлы, какие `R` закрывает, как проверить
   (тест). Задачи, трогающие одни файлы, — последовательно; остальные можно параллельно.
5. **Разработка.** На каждую задачу — субагент с чистым контекстом и только своим `T`: читает
   `CLAUDE.md`, `REVIEW.md`, `spec.md`, делает, пишет тест, который падал до правки, один коммит
   `T3: …`. Упала — одна повторная попытка, затем задача помечается заблокированной в `plan.md`,
   прогон идёт дальше.
6. **Проверки и ревью.** `/site-check` (lint, typecheck, test, format, build); `/code-review` по
   всему диффу ветки; подтверждённое исправляется с тестом. Затем `git diff origin/main | grep` по
   реквизитам владельца (урок 17 `tasks/lessons.md`).
7. **Приёмка** (`acceptance.md`). Таблица `R1…Rn` → выполнено / частично / нет, с доказательством
   (тест, файл, скриншот). Требование без доказательства считается невыполненным. Если
   невыполнено больше трети — PR остаётся черновиком, а не сливается.
8. **PR и выкладка.** Ветка `claude/autopilot-<дата>-<slug>` от свежего `origin/main`; описание PR
   по-русски: бриф, таблица приёмки, что не сделано, PLACEHOLDER-ы. Дальше — как в ежедневном
   цикле: CI зелёный → слить → проверить прод (`/api/health`, `/api/categories`) → при правках
   приложения опубликовать Expo-обновление (оба варианта). Пункт дорожной карты отметить
   «сделано <дата>, PR #n», открытые PLACEHOLDER-ы перенести в `docs/owner-requests.md` одной
   строкой каждый.

## Что нельзя

Фальшивые пользователи, заявки, отзывы, счётчики; рассылки без согласия; реквизиты и
персональные данные в репозитории; изменение решений владельца; изменение чужих
запланированных задач; `ALTER TYPE … ADD VALUE`. Что требует денег или решения владельца —
только строкой в отчёте.
