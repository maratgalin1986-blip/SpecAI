# Публикация приложения в RuStore

Пошаговая инструкция для владельца (2026-10-17). RuStore — магазин приложений VK для Android:
бесплатно, установка в один тап, российские пользователи ему доверяют
(`docs/launch-plan.md`, раздел 1). Google Play — позже, для него уже есть отдельная сборка
(`production-aab`, ниже).

Аккаунт разработчика создаёт **только владелец**: RuStore подтверждает личность через VK ID и
Госуслуги, сессия Claude этого сделать не может. Всё остальное — сборка, тексты, список
скриншотов — готово в этом файле.

## 1. Аккаунт разработчика

1. Откройте [console.rustore.ru](https://console.rustore.ru) и войдите через VK ID.
2. Выберите, от чьего имени публикуете: от организации (ООО) или как физлицо/ИП. Для
   «ИИСтройка24 от СпецПласт16» логичнее организация — тогда в магазине разработчиком будет
   ваша фирма. Реквизиты вводите прямо в форме RuStore; в репозиторий их не пишем, он публичный.
3. Пройдите проверку, которую попросит форма (подтверждение через Госуслуги, для организации —
   данные компании). Проверка занимает от нескольких часов до нескольких рабочих дней.
4. В профиле разработчика укажите e-mail для связи: **specplast16@mail.ru** (`SITE.email` в
   `apps/web/src/lib/site.ts`).

## 2. Сборка APK для RuStore

RuStore принимает подписанный APK. Профиль `production` в `apps/mobile/eas.json` собирает
именно его:

| Профиль          | Что собирает                         | Канал обновлений | Для чего                    |
| ---------------- | ------------------------------------ | ---------------- | --------------------------- |
| `preview`        | APK, внутренняя раздача по ссылке    | `preview`        | тесты, Expo Go (не трогаем) |
| `production`     | подписанный release-APK              | `production`     | **RuStore**                 |
| `production-aab` | подписанный AAB (Android App Bundle) | `production`     | Google Play, когда дойдём   |

Команда (из папки приложения, не из корня — иначе eas-cli создаст лишние файлы):

```bash
cd apps/mobile
npx eas-cli build --platform android --profile production
```

Сборка идёт в облаке Expo 15–30 минут и расходует квоту сборок аккаунта. В конце команда
печатает ссылку на страницу сборки; там кнопка **Download** — это и есть APK для RuStore.
Адрес API (`EXPO_PUBLIC_API_URL=https://spec-ai-web.vercel.app`) уже вшит в профиль.

### Номер версии (versionCode)

- В `eas.json` стоит `"appVersionSource": "remote"`: номер сборки Android (`versionCode`)
  хранит EAS, а не `app.json`. Сейчас он равен 1 (первая APK `preview`, 2026-10-15).
- У профиля `production` включён `"autoIncrement": true`: каждая магазинная сборка сама
  увеличивает номер (первая будет 2, следующая 3 и т. д.). RuStore требует, чтобы каждое
  обновление было с номером больше прежнего, — это и обеспечено, вручную ничего менять не надо.
- Версия для людей (`version` в `app.json`, сейчас `0.1.0`) меняется вручную, когда выходит
  заметное обновление с новым нативным кодом. От неё же зависит `runtimeVersion` (политика
  `appVersion`): обновления «по воздуху» (EAS Update) приходят только в сборки той же версии.
  Поменяли `version` — сделайте новую сборку и загрузите её в RuStore.
- Проверить номер: `npx eas-cli build:version:get --platform android --profile production`.

### Ключ подписи — беречь

Первая загрузка в RuStore закрепляет ключ, которым подписан APK; все обновления должны быть
подписаны тем же ключом. Ключ (keystore) создан EAS при первой сборке и хранится на expo.dev.
Сделайте резервную копию: `cd apps/mobile && npx eas-cli credentials` → Android →
`production` → Keystore → Download. Файл и пароли — в надёжное место, **не в репозиторий**.
Для Google Play этот же ключ станет ключом загрузки, Play переподпишет приложение своим.

## 3. Приложение в консоли RuStore

1. «Приложения» → «Создать приложение» → загрузите APK. Имя пакета подтянется из файла:
   **com.specai.specai** (`android.package` в `apps/mobile/app.json`). Пакет потом не меняется.
2. Заполните карточку текстами из раздела 5.
3. Загрузите иконку 512×512 (`apps/mobile/assets/icon.png` или `apps/web/public/icons/icon-512.png`)
   и скриншоты (раздел 6).
4. Политика конфиденциальности: **https://spec-ai-web.vercel.app/privacy**.
5. Возрастной рейтинг — анкета из раздела 7.
6. «Отправить на модерацию». Обычно 1–5 рабочих дней; замечания приходят на почту и в консоль.

Перед отправкой проверьте два места, к которым модерация может придраться:

- **Фоновая геопозиция.** Приложение просит доступ к геопозиции «всегда» — только исполнителю,
  который сам нажал «На линии», чтобы его машина была видна заказчикам на карте (уведомление
  «Вы на линии» висит, пока он на линии). В форме RuStore так и объясните. В
  политике конфиденциальности (/privacy) пока нет отдельного пункта о геопозиции телефона
  исполнителя «на линии» — его стоит добавить до отправки (сессии сайта: одна строка в список
  собираемых данных).
- **«Поддержать приложение»** (добровольный перевод на карту). Магазины строго смотрят на
  приём денег внутри приложения. Если модерация вернёт приложение с замечанием о платежах —
  выключите поддержку в меню администратора («Поддержка (донаты)») и отправьте снова; карточка
  пропадёт без новой сборки.

## 4. Обновления

Есть два вида обновлений.

**Обновление «по воздуху» (EAS Update)** — только JavaScript: тексты, экраны, логика. Новую
сборку и модерацию не требует; магазинная сборка слушает канал `production`. Публиковать в
`production` нужно **вместе** с `preview`, иначе пользователи из RuStore останутся на старой
версии. Как и для `preview` (урок 16 в `tasks/lessons.md`), — `--platform all` и дважды: для
сборки и для Expo Go:

```bash
cd apps/mobile
EXPO_PUBLIC_API_URL=https://spec-ai-web.vercel.app npx eas update --channel production \
  --environment production --message "описание изменений" --platform all
# та же версия для Expo Go (runtime «exposdk:57.0.0»), чтобы канал можно было открыть и в нём
EXPO_GO_UPDATE=1 EXPO_PUBLIC_API_URL=https://spec-ai-web.vercel.app npx eas update \
  --channel production --environment production --message "описание изменений" --platform all
npx eas update:list --branch production            # id и ссылки на обновления
```

Канал `production` появится на EAS после первой сборки этого профиля; до неё команда может
попросить создать канал — соглашайтесь (имя `production`).

**Новая сборка** — когда меняются нативные модули, разрешения, иконка, `app.json` или
`version`: `npx eas-cli build --platform android --profile production`, затем в консоли
RuStore «Новая версия» → загрузить APK → «Что нового» → на модерацию.

## 6. Скриншоты

Снимайте с телефона Android на установленной production-сборке (не в Expo Go), вертикально,
без личных данных: заведите тестового заказчика и тестового исполнителя, адреса — общие
(улица без номера дома). Порядок в карточке:

1. Главная заказчика: карта с машинами «на линии» и пузырём «Я на линии · машина · цена · имя».
2. Быстрый заказ: шторка с адресом, плитками видов техники и «Нужна сейчас / На дату».
3. Заказ с предложениями исполнителей: карточки с ценой и кнопкой «Выбрать».
4. Заказ по шагам: «Исполнитель выбран» → «В пути» (экран заказа как поездка).
5. ИИ-диспетчер: экран «Помощник» с подписью, что отвечает программа.
6. Лента исполнителя: переключатель «На линии» и заявки с «Предложить цену».
7. Смена машиниста: статусы «Выехал → На объекте → Работа» и табель.
8. Каталог техники (машины СпецПласт16 первыми).

Скриншот делается кнопками «питание + громкость вниз». Требования к размеру RuStore покажет в
форме загрузки; обычные снимки экрана телефона им подходят.

## 7. Возрастной рейтинг — ответы на анкету

- Насилие, страшные сцены, нецензурная лексика, сексуальные темы, алкоголь/табак/наркотики,
  азартные игры — **нет**.
- Покупки внутри приложения — **нет** (онлайн-оплаты нет; добровольная «Поддержка» — перевод на
  карту вне приложения, см. раздел 3).
- Пользователи общаются между собой — **да**: чат заказчика и исполнителя по заказу, отзывы
  (публикуются после модерации владельца, телефоны и ссылки в текстах скрываются).
- Приложение получает геопозицию — **да** (карта, «на линии» у исполнителей).
- Ожидаемый рейтинг: **0+** или **12+** из-за общения пользователей — оставьте тот, что
  предложит RuStore по анкете.

## 8. Проверка после публикации

- Установите приложение из RuStore на чистый телефон, войдите заказчиком и исполнителем.
- Опубликуйте пробное обновление в `production` (раздел 4) и убедитесь, что оно пришло:
  `npx eas update:list --branch production`.
- Ссылку на страницу в RuStore добавьте на сайт и в Telegram-бота (`docs/launch-plan.md`).
