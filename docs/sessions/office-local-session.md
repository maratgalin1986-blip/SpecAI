Облачная сессия офиса (`claude/pensive-feynman-bila02`) не может подключиться к компьютеру владельца:
папка в Remote Control есть, но облачным сессиям не отдаётся. Поэтому то, для чего нужен его браузер,
делает сессия, запущенная на самом компьютере. Облачная сессия продолжает код, поиск фирм и продакшен.
Обе сессии пишут сюда и в `docs/owner-requests.md`; память — в репозитории, а не в чате.

  затем «Отправил».
- `/admin/office/pisma` — письма дня; не уходят, пока нет ящика (`officeMail: false` в `/api/health`).

## Задачи сессии на компьютере

1. **Почта для писем.** Вместе с владельцем: в Яндекс ID создать пароль приложения для почты, в настройках
   почты включить IMAP/SMTP с паролями приложений; в Vercel → `spec-ai-web` → Settings → Environment Variables
   (Production) добавить `OUTREACH_SMTP_USER` (адрес ящика), `OUTREACH_SMTP_PASS` (пароль приложения),
   `OUTREACH_FROM` («ИИСтройка24 <адрес>»); затем Redeploy последнего Production-деплоя. Проверка:
   `/api/health` → `integrations.officeMail: true`. Пароль не выводить в чат, не писать в файлы и коммиты.
2. **WhatsApp.** Открыть `/admin/office/whatsapp`, по каждой фирме показать владельцу текст и открыть чат.
   **«Отправить» в WhatsApp нажимает владелец сам** — рассылка без участия человека запрещена
   (ч. 2 ст. 18 закона «О рекламе»); после его отправки нажать «Отправил». Не больше дневного лимита.
3. **Флажок «и на обычный мобильный»** в настройках офиса — включать только по слову владельца.

## Чего не делать

- Не собирать карточки 2ГИС или Яндекс Карт автоматически: запрещено их правилами (разбор — в
  `docs/owner-requests.md`, раздел 2026-11-10). Владелец может сам внести выбранные фирмы в «Добавить вручную».
- Не менять код офиса без согласования с облачной сессией: правки — через PR в `main`, перед работой
  `git pull`, уроки — `tasks/lessons.md` (39–42 — про этот запуск).
- Не трогать чужие расписания и секреты.
