# Правила проверки кода (REVIEW.md)

Этот файл читает проверяющий (человек или агент) перед обзором любого PR.
Нарушение любого пункта ниже — блокирующее замечание, а не «пожелание».
Проверка по этим правилам прогоняется перед каждым пушем
(`/code-review` в сессии Claude), а не только перед слитием.

## 1. Приватность — важнее любой функции

- Исполнитель видит заказчика только как «Анна П.» (`lib/customerPrivacy.ts`),
  пока бронь не CONFIRMED/ACTIVE/COMPLETED. Любой новый ответ API, экран или
  письмо, где исполнителю уходит имя, телефон, e-mail или адрес заказчика
  раньше, — ошибка.
- Телефоны, e-mail и ссылки в свободном тексте (описание заявки, заметка «на
  линии», чат, отзывы) маскируются `maskContactsAndLinks` / проверяются
  `containsContact` (`lib/privacy.ts`). Новое текстовое поле без маски — ошибка.
- Исполнитель видит только свои предложения (`lib/bidPrivacy.ts`). Ответ
  со списком чужих ставок, цен или компаний — ошибка.
- Телефон показывается только через «Показать телефон» (журналируется,
  ограничено по частоте). Прямой вывод `tel:` для исполнителя до
  подтверждения — ошибка.
- В ответах API не публикуются `User.id` других людей, внутренние заметки и
  служебные поля (`passwordHash`, токены, `telegramChatId` чужих).
- По IP посетителей не определяем (152‑ФЗ); персональные данные в браузере —
  только с согласия.

## 2. Доступ и роли

- Каждый маршрут `app/api/**` начинается с `getRequestUser(request)` (web и
  mobile) и проверяет роль: заказчик, админ компании-исполнителя, оператор
  (машинист), админ площадки. Маршрут без проверки роли — ошибка.
- Проверка владения: машина принадлежит компании, бронь — заказчику или
  компании, табель — своей брони. `findUnique` по id из запроса без `where`
  по владельцу — ошибка.
- Отключённый оператор (`active: false`) не выполняет действий.
- Статусы меняются только по разрешённым переходам (бронь: PENDING →
  CONFIRMED → ACTIVE → COMPLETED, отмена — из PENDING/CONFIRMED).

## 3. Деньги и цены

- Цены живут в `lib/prices.ts` и `lib/smetaPrices.ts`, тарифы машин — в базе.
  Число в рублях, вшитое в компонент или маршрут, — ошибка.
- Нижняя планка цены (`customerRates`) — только для парка СпецПласт16;
  чужим компаниям цены не навязываем.
- Парк СпецПласт16 всегда первый в списках (`houseFirst`, `HOUSE_FIRST_ORDER`).
- Суммы считаются в рублях целыми числами; округление один раз, на выводе.
  Деление цены многодневной брони — по дням, часы — по табелю.
- Онлайн-оплаты нет; любой новый платёжный шаг — только по решению владельца.

## 4. База данных и схема

- Изменения схемы — только добавление: новая модель, новая колонка с
  `?` или `@default`. Новое значение в существующем `enum` — ошибка
  (ломает деплой через пул). Переименование и удаление колонок — ошибка.
- `prisma db push` на деплое, миграций нет; код должен работать и со старой
  строкой (значения по умолчанию, `?? fallback`).
- Запросы со списками — с `take` и `orderBy`; `findMany` без ограничения на
  пользовательские таблицы — ошибка.
- Транзакции там, где меняются две таблицы вместе (бронь + предложения,
  смена + бронь, оператор + присутствие на линии).

## 5. Тексты и язык

- Все тексты для людей — по-русски, без англицизмов и слов «кабинет»,
  «вкладка», «сайт/приложение» в сообщениях об ошибках (пользователь может
  быть и там, и там). Понятная причина и что сделать: «Выберите машину, с
  которой выходите на линию».
- Название площадки — `SITE.platform` («ИИСтройка24 от СпецПласт16»),
  бренд не сокращается до «СП16».
- Имена моделей ИИ не попадают в код, комментарии, коммиты и тексты.
- Даты и «сегодня» — по Москве (`todayStartMsk`, `moscowDayKey`), не по
  часовому поясу телефона или сервера.

## 6. Решения владельца сильнее замечаний

Прежде чем менять поведение, проверить `docs/owner-requests.md` и
`tasks/lessons.md`. Действующие решения, которые проверка не отменяет:

- звук на публичных страницах включён по умолчанию (2026‑10‑03);
- агрегатор, а не единственный исполнитель (2026‑10‑06);
- регистрация с выбором роли, гостевая форма на /orders (2026‑10‑11);
- /stroyka, /smeta, /kalkulyator, /dizain убраны и редиректят на главную
  (2026‑10‑15);
- «на линии» только со свободной машиной, исполнитель не онлайн по
  умолчанию (2026‑10‑16).

## 7. Что обязательно до пуша

- `pnpm lint && pnpm typecheck && pnpm format:check && pnpm test`;
  `cd apps/web && npx next build`; при правках приложения —
  `cd apps/mobile && npx expo export --platform android`.
- Новая логика — с тестом (vitest); исправленный баг — с тестом, который
  падал до правки.
- e2e `apps/web/e2e/smoke.spec.ts` обновляется вместе с удалением или
  переименованием страниц.
- Слить `origin/main` перед пушем; после деплоя открыть
  `/api/categories` (200).

## 8. Как оформлять замечание

Файл и строка, что сломается и при каких данных, предлагаемая правка.
Замечание без сценария отказа — не замечание. «Стиль» и «можно иначе» —
только пометкой «необязательно», они не задерживают PR.
