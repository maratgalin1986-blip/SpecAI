## Ревью (воркфлоу, несколько линз, 2 голоса на находку) — исправлено

Карта доменов бралась с origin запроса (подмена Host) → только `siteUrl()`; утверждение было по строке, а не
по каналу; «Отказ» и «стоп» не ставили `optOutAt`, отписка проверялась только по почте; пачку в 50 строк
занимали кандидаты, которым нечего отправлять; строка могла начаться без времени на все отправки; «упавшие
сегодня» считались по `updatedAt` (любая запись прятала повтор) → новая колонка `outreachErrorAt`; напоминания
шли кроном в режиме «сам»; письмо обещало форму и WhatsApp, которых нет в превью, и «отправлено один раз»
перед напоминанием; лимит источника считал фирмы с сайтом; продление оплаты могло удвоиться со второй
вкладки; воронка считала снятые сайты; падежи в согласии и счёте; страница услуги говорила «уже делаем ваш
сайт» любому посетителю.

## Самооценка (10-балльная, честно)

- **Код и автоматика офиса — 9.** Поиск → досье → персональное предложение → письма дня → кнопка
  владельца → напоминание → отписка → клиент → счёт → домен работают и покрыты тестами (≈830 тестов офиса и
  страниц). Минус балл: нет чтения ящика ответов (IMAP), и К7/К8/К9/К11/К14 ещё впереди.
- **Юридическая готовность — 7.** Ручное утверждение, свой ящик, отписка, форма после оферты, политика ПДн
  есть; нужны заключение юриста и реквизиты в настройках.
- **Готовность приносить деньги сегодня — 5.** Писем ещё не ушло ни одного: нет ящика с SMTP в Vercel, нет
  `CRON_SECRET` в GitHub (шаги поиска идут только из дневного крона Vercel). Как только владелец сделает три
  шага из `docs/owner-requests.md`, офис каждый день готовит письма и ждёт одной кнопки.
