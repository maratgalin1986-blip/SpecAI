## Ревью (воркфлоу, несколько линз, 2 голоса на находку) — исправлено

Карта доменов бралась с origin запроса (подмена Host) → только `siteUrl()`; утверждение было по строке, а не
по каналу; «Отказ» и «стоп» не ставили `optOutAt`, отписка проверялась только по почте; пачку в 50 строк
занимали кандидаты, которым нечего отправлять; строка могла начаться без времени на все отправки; «упавшие
сегодня» считались по `updatedAt` (любая запись прятала повтор) → новая колонка `outreachErrorAt`; напоминания
шли кроном в режиме «сам»; письмо обещало форму и WhatsApp, которых нет в превью, и «отправлено один раз»
перед напоминанием; лимит источника считал фирмы с сайтом; продление оплаты могло удвоиться со второй
вкладки; воронка считала снятые сайты; падежи в согласии и счёте; страница услуги говорила «уже делаем ваш
сайт» любому посетителю.

## Четвёртая волна (2026-11-10): запуск на продакшене и то, что он показал

Продакшен 10.11: за сутки после выката кандидатов было ноль — Overpass не отвечает с Vercel. Сделано:
поиск через раннер GitHub (`office.yml` → `/api/cron/office/next` → Overpass → `/ingest`), самодиагностика
(`/api/health` → `office`, плашка в админке, первая строка сводки), числа «конкурентов рядом» только по полному
списку, страница предложения `/kp/<токен>`, очередь «WhatsApp вручную», кнопка «Проверить ящик», запрет на
хранение данных 2ГИС без договора. Повторная проверка вечером (три проверяющих + замеры с раннера) нашла и
закрыла: ложное «работаете в выходные» при «Sa,Su off»; два письма на один адрес и повтор при втором нажатии
кнопки; потерю каждого второго шага поиска из-за таймаута зеркал (теперь шаг откладывается и повторяется);
разбор часов работы стал строгим (незнакомое слово в часах — и по ним ничего не утверждается);
запрос спецтехники, который не успевал никогда; устаревшие строки в документах.

Проверено на продакшене (числа из `/api/health` и журнала GitHub Actions, 10.11): автосервисы Казани 91 / 25,
салоны красоты 317 / 30, бухгалтерские услуги 6 / 2; очередь — 100 фирм (16 с почтой, 45 с мобильным).
Расписание GitHub срабатывает раз в 4–9 часов, а не каждый час. После слияния PR #122 проверено боевыми
запусками (10.11 22:27 и 11.11 05:13 МСК): 6 шагов подряд без ошибок; шаг «спецтехника; Лениногорск» не
дождался ответа, был отложен и через два шага повторён успешно; очередь выросла до 252 фирм (67 с почтой,
155 с мобильным). Проверено только тестами (отправки на продакшене ещё не было): защита от повторных писем,
захват строки перед отправкой, строгий разбор часов в тексте писем.

## Самооценка (10-балльная, честно)

- **Код и автоматика офиса — 9.** Цепочка поиск → досье → персональное предложение → письма дня → кнопка
  владельца → напоминание → отписка → клиент → счёт → домен работает и покрыта тестами (≈ 700 тестов офиса,
  2 611 всего). Минус балл: ответы на почту офис не читает (IMAP), К7/К11/К14 не сделаны, агент
  «Подрядчики» из OpenStreetMap даёт единицы фирм на город, в Москве и Петербурге ищет только по узким тегам.
- **Юридическая готовность — 7.** Ручное утверждение, свой ящик, отписка, форма после оферты, политика ПДн
  есть; заключения юриста и реквизитов в настройках нет. С 11.11 по решению владельца режим по
  умолчанию — «сам по расписанию» (первые письма без его просмотра, с 8 до 20 по Москве): это его риск по
  ч. 2 ст. 18 закона «О рекламе», балл не выше прежнего.
- **Готовность приносить деньги сегодня — 6.** Очередь на пять дней отправки готова, предложения
  персональные. Но фирмам не отправлено ни одного письма и ни одного сообщения: в Vercel нет пароля ящика
  (`OUTREACH_SMTP_PASS`), а «Отправить» в WhatsApp и в «Письмах дня» нажимает только владелец. Продаж нет.
- **До 10 кодом не дотянуть:** оставшиеся баллы — это первая отправка, первые ответы и первая оплата.
